Comece por estes pontos

O GC analisado é React para navegador. As listas usam .map(). FlatList é um componente do React Native; não aparece como implementação de lista desta versão. Não confunda uma página responsiva com um aplicativo React Native.

Priorize login, estado/input, listas, busca, CRUD de anotações, persistência e permissões. Os demais exemplos ajudam quando pedirem um detalhe pequeno: contador, botão desabilitado, avatar, tema, modal ou teste.

No VS Code: Ctrl+P abre um arquivo pelo caminho e Ctrl+G vai à linha. Os links deste guia abrem a versão exata consultada no GitHub. As linhas podem mudar em commits futuros.

Os blocos abaixo são recortes reais; não substituem arquivos completos. A numeração na margem foi acrescentada pelo guia. Nenhum arquivo do repositório foi alterado para esta análise.

02 Login: verificação da senha no servidor

Na demonstração: Abra esta rota depois de mostrar o formulário.

find localiza o usuário. verifyPassword compara a senha recebida com o hash armazenado. Credenciais incorretas geram 401; conta inativa gera 403. Após validar, o servidor cria uma sessão. scrypt e salt aleatório produzem o hash; ele não é uma criptografia reversível.

Você pode explicar assim: “O servidor decide se o login é válido. Ele verifica o hash da senha e devolve um token de sessão.”

04 Sessão, localStorage e logout

Na demonstração: Entre, recarregue a página e depois saia.

applyAuth guarda o token no localStorage e o usuário no estado. Ao carregar, AuthProvider consulta /auth/me para verificar se a sessão continua válida. SessionStore guarda sessões em memória com expiração; reiniciar o servidor encerra essas sessões. Logout invalida a sessão no servidor e limpa o estado local.

Você pode explicar assim: “O navegador envia um token para se identificar, e o servidor verifica se essa sessão ainda existe.”

07 Busca: .filter(), .includes() e useMemo

Na demonstração: Pesquise um nome, cargo ou e-mail; depois procure um termo inexistente.

trim remove espaços nas pontas e toLocaleLowerCase padroniza a comparação. filter seleciona itens e includes procura o texto. useMemo reutiliza o resultado enquanto members e query não mudam. Essa busca ocorre no navegador, sobre os dados já carregados.

Você pode explicar assim: “A busca filtra a lista recebida da API pelo nome, e-mail ou cargo.”

Perguntas rápidas para ensaiar

O GC tem FlatList?A versão analisada usa React web e .map(). FlatList pertence ao React Native e oferece recursos de listas virtualizadas; .map() sozinho não faz isso.
Onde os dados ficam salvos?No JSON ativo da API: data/gc-demo.json em desenvolvimento ou release/data/gc-demo.json na release. seed.json contém os exemplos iniciais.
Por que atualizar useState se já salvou no arquivo?Salvar mantém os dados; atualizar o estado faz a interface refletir o resultado sem precisar recarregar manualmente.
A senha está criptografada?O termo correto aqui é hash de senha com scrypt e salt. O sistema compara um hash calculado; não descriptografa a senha.
É JWT?Não. É uma sessão opaca: o token identifica uma sessão armazenada na memória do servidor.
Ao reiniciar o servidor, tudo some?As sessões em memória são perdidas; os registros já persistidos no JSON permanecem. Será necessário entrar novamente.
Onde o perfil é salvo?SettingsPage chama saveSettings; AuthProvider envia PATCH /settings e atualiza o usuário e as preferências. A API persiste a alteração.
Esconder o botão garante a permissão?Não. A proteção precisa existir na API; o GC também verifica as permissões no servidor.
É um banco relacional?A versão estudada é JSON local. Não usa tabelas MySQL; a versão GC-SQL é outro projeto.
Todo o app precisa de internet?As funções locais podem operar sem internet depois de preparado o ambiente. Os mapas externos dependem de conexão.
A seleção do mapa é Google Maps?A seleção usa Leaflet/OpenStreetMap e gera links que abrem as coordenadas no Google Maps.
Posso provar que funciona olhando o código?O código explica a implementação; executar os fluxos e testes comprova o comportamento na cópia local. Este guia é uma leitura do código, não um relatório de testes executados.

npm run start:release

Abra http://localhost:3000. Para desenvolver e ver alterações no código-fonte:

npm install
npm run dev

Abra http://localhost:5173. Alterar o código-fonte não atualiza automaticamente uma release já compilada; npm run build a recompila.
